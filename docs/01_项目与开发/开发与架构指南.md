# 开发与架构指南

本手册说明模块职责、对象生命周期和开发约束，工程组织更新至 2026-10-12；历史验证保留各自日期与适用范围。文本字段、HDF5 数据集及数值公式分别见[文本模型格式](../02_模型与格式/文本模型格式.md)、[HDF5 文件格式](../02_模型与格式/HDF5文件格式.md)、[索单元理论与验证](../03_求解理论/索单元理论与验证.md)和[求解执行与收敛](../03_求解理论/求解执行与收敛.md)。下文工程路径均以包含 `YQY.sln` 的仓库根目录为基准。

## 1. 工程与构建

YQY 是面向架空输电线路及一般杆系结构的 CAE 桌面程序，提供模型生成、前处理、静力/动力求解、结果查看和导出。当前主工程采用 C++20、MSVC v143、Qt 6.8.2、VTK 9.4.2、Eigen、HDF5，并接入 oneMKL/PARDISO、CUDA 和 cuDSS；具体路径和库版本以工程属性文件为准。

- [YQY.sln](../../YQY.sln) 管理解决方案；[YQY.vcxproj](../../YQY/YQY.vcxproj) 管理生产编译与部署，[YQYTests.vcxproj](../../YQYTests/YQYTests.vcxproj) 管理测试。
- 测试按实体目录分类，不使用 `YQYTests.vcxproj.filters`，VS 启用“显示所有文件”。新增源码必须登记到 `.vcxproj`；虚拟筛选器不改变磁盘目录或构建。
- 生产 `YQY` 保留应用功能和通用数值实现；C++ 算例放在 `YQYTests`，必要模型和参考位于 `YQYTests/TestModels`。独立的算例生成、比较和批量运行脚本已移除；产品结果绘图脚本 `YQY/Tools/result_plot.py` 继续由界面调用。
- 第三方库放在仓库根 `ThirdPartyLibrary`，Qt、CUDA、VS 工具链另行安装。恢复方法见[第三方依赖说明](../../THIRD_PARTY_DEPENDENCIES.md)。旧机器的 D 盘路径只是部分属性中的历史回退，不是目录部署要求。
- `Debug|x64`、`Release|x64`、`ReleaseVerification|x64` 均配置生产项目和独立测试项目。原 `ReleaseVerification` 名称及生产产物名保留，但测试入口统一位于对应配置的 `YQYTests.exe`，生产 EXE 不再承载验证分派。

在已配置 MSBuild 的开发者 PowerShell 中，可分别构建：

```powershell
msbuild YQY.sln /m /p:Configuration=Release /p:Platform=x64
msbuild YQY.sln /m /p:Configuration=ReleaseVerification /p:Platform=x64
msbuild YQY.sln /t:YQYTests /p:Configuration=Release /p:Platform=x64
.\x64\Release\YQYTests.exe
```

生产工程的 `ExportYQYRuntime` 目标从本次链接对象中排除 `main`，生成同配置的 `YQYRuntime.lib`，测试工程链接这份共享生产库，不重复编译生产实现或链接 EXE。当前 Qt、VTK 和生产库均使用 `/MD`，三个测试配置也使用 `/MD` 及 GoogleTest Release 库；Debug 保留 `/Od`、PDB 与调试检查。改为 `/MDd` 时必须同步整条依赖链，不能只修改测试一侧。

对象库仅由正式目标 `YQY`、`YQYVerification` 导出，并在导出前检查实际链接输入包含 `main.obj` 和 `Outputter.obj`。临时检查程序使用其他目标名时跳过导出，避免共享输出目录中的完整生产库被单个探针对象覆盖，进而造成测试的 `LNK2001/LNK2019`。

当前 Qt 6.8.2 与 VS 17.14.39 环境曾在 `qrunnable.h` 报出 IntelliSense `E2422`；工程使用 C++20，命令行编译通过。工程保持 Qt 原始声明，不通过宏改写 `dllimport`、关闭诊断或修改 Qt 安装文件绕过分析器。此项编辑器问题与测试链接错误分别核验；命令行构建通过不代表 IntelliSense 误报已修复，也不能据此认定任意更新版本已解决该问题。

自有代码遵循根目录 [AGENTS.md](../../AGENTS.md) 和 `.clang-format`：中文说明性注释、120 字符行宽、Allman 花括号；通过引用或指针返回结果的参数在声明和定义中一致标记 `_OUT`。重构前保留已有未提交修改，每批逻辑变更编译并运行相关回归，不改第三方、自动生成代码和构建目录。

## 2. 职责和主数据流

| 模块 | 当前职责与入口 |
| --- | --- |
| `Application`、`main.cpp` | 初始化运行环境，进入桌面程序或独立的 `SolveWorker`；`ApplicationPaths` 统一资源和产物路径 |
| `YQYTests` | 按实体目录维护单元、集成、论文和界面测试；统一 GoogleTest 与原验证参数入口，链接共享生产代码 |
| `GUI` | 主窗口编排、面板与对话框、VTK 模型/结果视口；`ProgressBarAnimation` 管理进度动画 |
| `GUI/Controllers` | `ModelController` 管理多模型文档、异步加载和节点编辑撤销；`SolveTaskController` 管理任务准备、依赖、队列、取消和完成状态 |
| `DataStructure` | 节点、材料、截面、属性、单元、弹簧行为、荷载、约束、惯性、集合、区域和分析步；`StructureData` 持有完整模型 |
| `Conductor` | 导线几何和业务建模；`ConductorModelBuilder` 将几何结果变为模型实体，处理编号、属性、附件、集合和多档连接 |
| `Solver` | `AnalysisRunner` 组织分析步和区域任务；求解器、时间积分、矩阵装配、线性解法、MPC 和阻尼完成数值计算 |
| `Import` | `Input_Model` 读取文本字段、关联实体并校验模型，保留各格式的兼容规则 |
| `Export` | HDF5 模型序列化、结果流写入/读取、BDF 结果导出；`Outputter` 管理求解帧和迭代记录 |
| `Base`、`Utility` | 公共基类、枚举映射、共旋工具、日志和既有模型查找设施 |

典型数据流：

```text
文本/H5 导入或导线生成 → StructureData → ModelController → 前处理视口
                                                ↓
                         SolveTaskController → AnalysisRunner → AnalysisStep/ISolver
                                                ↓
                            Outputter/HDF5 → 结果 DTO → 后处理视口/导出
```

GUI 负责交互，控制器负责生命周期，领域模型保存定义和状态，求解层负责数值计算，IO 负责格式转换。不要把界面提示写进格式代码，或让求解器依赖控件。头文件优先暴露接口和轻量数据，具体读写器、求解器及绘制实现放到需要它们的 `.cpp`。

界面统一使用 `.h/.cpp` 创建 Qt Widgets 控件与布局，不再维护 `.ui` 文件或 `QtUic` 工程项。沿用 GUI 现有的 `initialize...`、`refresh...`、`update...` 和 `m_...` 命名；需要后续交互的控件由窗口持有成员指针，仅用于组装布局的控件使用局部变量，生命周期由 Qt 父子关系管理。`objectName`、翻译上下文、用户可见文本和输入参数范围保留现有语义。

主窗口布局在 `GUI/YQYLayout.cpp` 中按导航、模块页面、视口工具栏、监视器和状态栏组织；导线布局在 `GUI/Widgets/ConductorModuleLayout.cpp` 中按参数组和选项卡组织，两者仍是原窗口类的成员实现。分析步、荷载、约束和 MPC 编辑器各有独立头源文件，继续通过 `AnalysisEditorFactory` 创建；共享显示规则集中在 `Utility/AnalysisDisplay`。结果导出对话框的实现放在对应 `.cpp` 中。界面布局调整仍需编译并检查实际窗口，不以文本比对替代交互检查。

`Application/SolveWorker` 直接依赖模型、序列化器和求解运行器，无界面进程入口不再由 GUI 控制器声明或实现。
线程及进程的耗时诊断共用 `Utility/AnalysisDiagnostics`；`AnalysisSolve.h` 只前置声明模型，避免传递包含完整领域实现。
`RuntimeOptions::ModelFiles` 统一提取桌面位置参数，求解器和输出选项不再交给模型读取器；`--` 之后按文件路径处理。

主窗口、`Hdf5ModelIO.cpp`、`ConductorModelBuilder.cpp`、`ModelViewport.cpp` 和 `Input_Model.cpp` 仍是较大的实现文件。后续按稳定职责逐批提取辅助逻辑；移动代码时保持公式、计算顺序、容差、文件字段和界面行为，不通过更换质量模型或求解算法取得表面的代码缩减。

## 3. 模型、荷载和导线业务规则

[StructureData](../../YQY/DataStructure/Structure/StructureData.h) 持有按 ID 索引的实体容器。节点保存坐标、运动状态、力和自由度；单元引用节点与属性，属性引用材料与截面。`FindNode`、`FindElement` 返回 `shared_ptr`，查找失败返回空指针，调用方不能沿用旧文中的弱指针 API 示例。

当前普通单元创建入口支持 `T3D2`、`CABLE`、`CR3D`、`SPRING1`、`SPRING2`、`SPRINGA`。`CR3D` 对应 `ElementBeam_CR`；`ElementBeam_Simo` 是另一份单元实现，不能据此把文本关键字写成 `B31` 或把旧 `ElementBeam` 类名当成现行接口。节点的实际自由度随单元及区域裁剪确定，索的转动状态也不能简化成“所有节点固定三个自由度”。

采用一致单位制：长度 m、力 N、时间 s、应力/弹性模量 Pa、材料密度 kg/m³、面积 m²、截面惯性矩 m⁴。转角和荷载时间函数相位通常为 rad；明确带 `Degrees` 的风攻角等字段使用度。初始应力使用 Pa，拉应力为正。不同索本构分支有自己的拉压和参考状态规则，修改前应查阅理论专题与当前实现，不能用旧说明中的单一公式替代。

荷载有节点力、单元力、重力和风四类，基础数值分别代表力、单元荷载、重力加速度和风速。时间函数由 [LoadBase](../../YQY/DataStructure/Load/LoadBase.h) 管理：`CONSTANT`、`SIN`、`COS`、`RAMP`、`EXPONENTIAL`、`TRIANGULAR`、`SQUARE`。作用窗口包含两端，函数使用相对 `StartTime` 的局部时间，窗口外或非有限函数结果缩放为零；频率为 Hz。多个荷载独立求缩放后参与装配。

分析步作用域见 `AnalysisStep::IsStepScopedDataActive`：

- `StepId <= 0` 为兼容的全局作用域；当前步定义生效。
- 静力步及没有前置平衡步的动力步，沿用较小分析步 ID 的定义。
- 指定 `InitialStaticStepId` 的动力分支只继承该静力步及此前定义，不能带入其他同级动力分支。
- 已继承的历史荷载按全额作用；当前步荷载才应用当前时间窗口、时间函数及当前荷载系数。参考无风静力平衡会排除风荷载。

文本导入会执行模型清理，包括重复节点合并、重复单元和孤立节点删除及重新编号；H5 恢复和运行期区域副本的编号规则与其不同。这里的“全局 ID”指同一文档模型内的 ID，区域副本不另建一套局部节点/单元号。清理后的 ID 与原文本行号不能混用。

导线几何入口位于 [Conductor.h](../../YQY/Conductor/Conductor.h)，当前命名空间是 `Conductor`。分裂数由调用方明确提供，支持 1、2、4、6、8；水平张力 N 和线重 N/m 由建模服务根据应力、材料及截面推导。使用 [ConductorModelBuilder](../../YQY/Conductor/ConductorModelBuilder.h) 生成实体，避免业务调用方重复创建节点、属性和附件。多档模型共享中间站子导线端节点；间隔棒及悬垂/耐张附件须遵守同一 `wireId` 方位约定，束截面旋角须通过现有合法性检查。

`DataStructure/Aerodynamics/AeroManager` 按工况管理 CSV 中的升力、阻力和力矩系数，提供周期攻角插值及系数斜率，支持现有线性和保形插值设置。原始 0°/360° 测量端点可能不一致，周期闭合用于插值，不应借此覆盖原始数据；数据来源、单位及稳定性判断见[气动数据与稳定性判据](../04_气动与舞动/气动数据与稳定性判据.md)。

## 4. 所有权、后台任务和结果数据

`StructureData` 通过 `shared_ptr` 持有实体，实体之间大量使用 `weak_ptr` 关联；使用前必须检查 `lock()`。弱引用避免循环持有，也意味着只复制指针或容器不会得到独立计算模型。

文本及 HDF5 模型先在临时 `StructureData` 中解析、清理并验证，失败时保留调用方模型；成功后统一调用
`ReplaceModelFrom` 提交。该方法保留目标对象身份，移入模型定义、输出配置及气动数据，不移入临时求解结果。
IO 层不再自行逐容器替换领域状态。`Clear` 同时清理弹簧行为、结果流和模型定义，避免复用对象残留旧配置。

`CloneForAnalysis` 重新创建节点、材料、截面、属性、单元、弹簧行为、荷载、约束、MPC、刚体惯性、分析步、集合与区域，并把引用绑定到副本实体。它保留既有物理状态和配置，不共享可修改的节点/单元状态、求解器或结果流；新增实体字段时必须同步检查这条复制链。`LoadFactory::Clone` 自身保留源弱引用，重新绑定由 `StructureData` 完成。

`ModelController` 持有界面文档。`SolveTaskController::prepare` 先制作任务模板，执行或重启时再从模板或已收敛的前置状态复制；工作线程只修改该任务的计算模型。进度与完成事件通过 Qt 队列回到控制器线程，取消标志使用原子变量。控制器析构时等待后台任务结束，不能留下捕获已销毁控制器的回调。运行中的模型拓扑与 ID 不应被界面编辑操作修改。

异步模型加载的当前文件一直保留到完成事件被接收，去重覆盖正在读取和待处理的请求；仅凭
`QFutureWatcher::isRunning()` 无法区分后台已结束但结果未交付的情况。替换活动文档同步清空撤销状态。
求解执行方式在提交任务时冻结；隔离进程的多区域进度、取消检测分别加锁，进度协议按完整行输出。
结果帧缓存读取前先失效索引，失败后不复用被清空的数据；节点时程切换文件会使旧查询结果失效。

任务并发、区域并发、单元装配和 PARDISO 各有线程预算，控制器先为界面及系统预留处理器，再将预算分配给任务和区域，避免多层并行相乘。`AnalysisRunner` 已有区域线程池和相应装配限额，这不是尚待实现的并行计划。GPU 批处理和线性解法由现有设置及回退机制控制。完整算例还支持显式启用的试验性独立进程模式，不能把该模式当成所有任务的默认执行方式。

HDF5 的公开职责分成三类：[Hdf5ModelSerializer](../../YQY/Export/Hdf5ModelSerializer.h) 处理模型及状态恢复，[Hdf5ResultWriter](../../YQY/Export/Hdf5ResultWriter.h) 管理结果流，[Hdf5ResultReader](../../YQY/Export/Hdf5ResultReader.h) 管理摘要、索引和按帧读取。它们复用 `Hdf5ModelIO` 底层实现，不是三套文件格式。

- 模型与分析配置位于 `/YQY/INPUT`，计算结果位于 `/YQY/RESULT`，`/INDEX` 保存帧索引。模型文件可没有结果分组；导入 H5 不等于自动恢复最后一帧动力状态，后者有独立入口。
- 流开始时标记 `RESULT_COMPLETE=0`，正常结束才按完成状态更新；存在结果帧但未完成的文件应显示为部分结果。正式模型写入保留原子替换，`directWrite` 仅用于独占临时快照。
- HDF5 在分配或读取之前检查维度、标量属性长度和结果索引范围；负长度、重复域和超范围索引拒绝读取。
  正式文件替换失败保留旧目标；发生分批写入错误的临时流不得提交，正常取消产生的有效部分结果仍可保留。
- `Hdf5ModelIO` 持有文件句柄及中文路径适配所需临时路径的生命周期，不可复制。底层 API 有进程内互斥保护，但读写器及结果流仍应由所属任务管理，不能据此让多个任务写同一个文件。
- 区域子任务关闭独立流式输出，完成后由父任务合并帧并保存，避免并发写同一 H5。单区域完整模型可使用直接求解路径，其上层任务模型仍与界面文档隔离。

GUI 保存和显示的是 [Hdf5ResultData.h](../../YQY/Export/Hdf5ResultData.h) 中的摘要、帧索引、节点/单元结果和范围 DTO，不应因持有这些值而包含完整 IO 头文件。`ResultFrameUtilities` 负责内嵌模型匹配和相邻帧插值，沿用原容差、字段处理及缺失数据规则；展示插值不改变求解时程。

## 5. 计算区域与分析步

### 定义、闭包与合并

完整模型保存全部节点和单元，包含塔架等仅用于显示的对象。`ModelSet` 只保存节点或单元的 ID 集合；`ComputeRegion` 保存直接选择、来源集合及解析后的节点/单元成员，不持有另一份几何模型。分析步选择已有区域，不负责新建或拆分区域。

`RebuildAndMergeComputeRegions` 的规则是：

1. 从直接选择和来源集合重建成员。只选择节点且未给定单元时，纳入所有端点均被选中的单元；选择单元时自动补齐端点。
2. 沿 MPC 主从连接反复补齐另一端，覆盖 MPC 链和不直接连接单元的中心主节点。
3. 两个候选区域共享任意节点或单元时合并，重复执行直至没有重叠；共享端点和 MPC 闭包都可能触发合并。合并保留代表区域 ID，并改写分析步中被合并的区域 ID。
4. 验证成员引用、非空计算单元和 MPC 完整性；独立区域不能仍有共享节点或单元。删除区域会移除分析步内对应 ID，不应留下悬空绑定。

这套规则只合并已定义的区域，并不自动把未选的整座塔架或全图连通分量加入区域。来源集合、拓扑或 MPC 改动后，应重新解析并验证，再准备任务。

### 默认配置与启用状态

`EnsureDefaultAnalysisConfiguration` 仅在缺失时补齐配置：没有区域而有单元时，创建包含全部单元、端点及必要 MPC 节点的自动默认区域；第一次显式创建区域会替换唯一的自动默认区域，避免默认全模型重新覆盖用户选择。没有分析步而已有区域时，创建静力默认步：总时长 1、步长 0.01、容差 `1e-5`、最大迭代 50，作用于全部启用区域。已有分析步的算法和参数保留；未显式指定区域范围的配置默认为 `AllEnabledRegions`。

`SelectedRegions` 保存明确区域 ID，`AllEnabledRegions` 在运行时解析目标。当前 `SynchronizeComputeRegionEnablementFromSteps` 会重算区域启用状态：存在“全部区域”步时启用全部区域，否则仅启用被分析步引用的区域。因此 `m_Enabled` 不是可脱离分析步绑定长期独立维护的开关。无有效启用区域时求解失败，不静默运行全模型。

### 区域副本和边界

`CloneRegionForAnalysis` 从完整独立副本裁剪，保留该区域节点/单元及指定分析步：

- 节点力、单元力、普通约束和刚体惯性按保留实体过滤；MPC 按主节点归属保留并要求两端完整；重力、风等区域性荷载保留，在子模型内装配。
- 根据实际保留单元重设节点自由度，过滤不适用约束，避免塔架梁裁剪后给纯杆系留下零刚度转动行。
- 原模型中被裁剪单元与区域相接的节点属于截断边界；副本在尚未约束的保留自由度上补零位移“区域截断支座”。这会影响子模型边界条件，只修改分析副本，不回写原模型、集合或用户约束。
- 同一分析步的多个独立区域使用相同求解配置，运行状态独立；结果沿用完整模型 ID 合并，未参与计算的对象继续按原模型显示。

### 静力平衡与动力分支

独立分析步不因 ID 相邻而自动继承另一步的可变状态。动力步明确指定 `InitialStaticStepId` 后，前置步必须存在、类型为静力、ID 小于动力步，并覆盖动力步的全部目标区域。

现有动力积分器尚未实现运动支座的完整速度、加速度及质量耦合，动力入口明确拒绝当前步内变化的
规定位移和与初态不相容的固定位移跳变，不再静默忽略。恒零约束和与已继承初态相容的恒定位移允许使用。
历史静力约束时程冻结在前置静力终点，当前动力步专用时程按动力区间检查所有拐点，不能只比较两端。

`AnalysisRunner` 按“静力步、区域、参考无风平衡模式”组织平衡状态，避免同一依赖重复计算；每个动力分支从平衡状态再次复制，互不污染。控制器单步任务也复用已完成的前置任务及区域状态。选中的静力结果和正常前置静力结果按现有规则合入分支 H5；参考无风平衡使用专门路径，不得和普通含风平衡状态混用。

参考 TSSBN 的无风静力平衡属于内部初态准备，不是新增的模型分析步。控制器保留独立前置任务；求解列表、批量操作计数和结果算例列表仅列出用户分析步，动力任务等待期间由监视器显示前置平衡进度。内部初态结果不自动载入后处理。

`taskInfo()` 保留真实求解状态；`displayTaskInfo()` 只为列表与监视器提供显示快照。原静力任务仍为待运行、且现有动力任务关联的参考无风初态已经启动时，对应静力行展示该初态的进度，明确标注“初态计算中”“初态完成”等状态。隐藏初态任务的更新也刷新此行，动力排队等待时标注“等待静力”。原静力任务单独启动后始终展示自己的状态，不把无风初态误记为原静力正式求解完成；普通动力仍直接关联原静力任务。

行内停止与监视器使用当前显示的实际执行任务编号，运行按钮仍启动原逻辑任务。停止共享初态会按现有依赖规则阻止等待它的动力任务启动。批量调度、结果选择和自动载入继续读取真实任务，显示快照不产生新的正式结果。

2026-10-15 Release 回归使用已有 H5 小模型，普通链、参考链、参考静力复用三项任务链验证通过；真实界面分别只点击普通和参考动力行，验证前置静力状态同步以及随后独立启动原静力步。诊断与截图保存在 `tmp/task-chain-display-20261015`，未新增模型输入参数。

### 动力算法接入与公共任务生命周期

`SolverFactory::DynamicAlgorithms()` 统一登记目前六种动力算法的名称和执行策略，界面列表、参数验证、任务控制器和区域运行器共用这份登记。`DynamicExecutionPolicy` 声明初态模式、是否必须继承静力或启用舞动、是否将前置静力帧纳入动力结果。算法专属的积分和参数检查仍由对应实现承担，任务层不再分别判断参考算法名称。未登记或尚未实现的算法明确拒绝创建，编辑器保留并标识旧文件中的不可用类型，不会默默换成其他算法。

登记同时声明非线性 MPC 和规定边界运动的能力。两种 RK4 暂不支持非线性 MPC；目前六种动力算法都没有完整实现普通位移边界的运动时程。随时间变化的规定边界、以及与初态不兼容的位移跳变明确报错，避免条件被静默忽略后仍报告成功。恒零时程可正常使用；前置静力中已经生效并收敛的固定支座可保持其平衡位移，这不表示动力过程会重新播放静力支座时程。规定运动的完整实现还需要一致的固定自由度速度、加速度、质量耦合和阶段回滚，不能仅修改输出位移。

提交动力 worker 前，主线程冻结该轮使用的静力模型与区域平衡状态。worker 使用当前动力定义及冻结初态；后来刷新模板或重算静力不会清掉已经提交的初态。继承区域状态时，`CopyAnalysisBindingsFrom()` 复制当前定义的荷载、普通约束、MPC 和刚体集中惯性，并将节点、单元引用重绑到保留平衡状态的目标实体；四类全部校验成功才统一替换，不改节点、单元平衡状态或源模型。

“全部计算”按调用前待运行的用户任务计数，自动启动的前置静力也计入，内部准备任务只随依赖启动。“全部重算”先停止整批旧任务并等待 worker 收尾，再统一作废旧初态、按依赖顺序启动新批次，任务创建 ID 不决定求解先后。等待屏障期间拒绝新的启动请求；“停止全部”清除待重启批次和重启请求，并将尚未提交 worker 的等待任务正常收尾。前置静力停止时，等待动力同步停止；前置静力求解失败时，等待动力报告失败。界面根据 `waitingForInitialStatic` 字段显示等待状态，不解析日志文字。

依赖链执行中断时，也统一保存本次已经生成的有效结果帧并标记部分结果；参考初态仍不混入正式动力结果。没有新帧时不覆盖原文件。已经接受停止请求、但成功通知尚未提交的任务，在主线程收尾时按停止处理，不再释放等待动力启动。

新增动力算法须实现 `ISolver` 并登记工厂创建分支、名称与执行策略，补充对应数值参数校验；随后通过算法身份、静力依赖、共享依赖、停止、重算、进度和 H5 结果归属检查。公共生命周期检查与积分器自身的精度、稳定性验证分别承担职责，任务链通过不能代替数值正确性证明。

2026-10-16 的 `Release|x64` 正式程序与验证程序构建通过；15 项 `SolveTaskTest` 专项及 145 项默认回归全部通过。使用既有普通、参考 H5 模型的字节一致副本，六种动力算法的完整静力依赖链、参考初态复用以及两轮真实界面检查均通过，验证前置先后关系、共享初态、独立且单调的进度、结果归属及达到终时刻。固定步长 RK4 在原 `0.001 s` 步长下不稳定，最终任务链复核显式使用内存覆盖的 `0.0001 s`，原失败日志保留；其他数值参数及原模型文件未改写。报告、源码和程序 SHA-256、执行命令与截图见 [框架验收记录](../../YQY/Export/ExportFile/验证归档/storage_cleanup_20261016/records/solver-framework-20261015/validation.json)。这些短算例不替代全时程舞动及各积分器精度验证；全模型物理编辑的统一版本失效机制尚未增加，修改坐标、材料或截面后仍须重新准备并重算静力及动力链。

区域管理和分析步编辑应分别维护区域来源及求解配置。今后增加其他模型格式时，也必须保存完整实体、集合、区域、分析步绑定和全局 ID，并复用同一缺省规则；旧设计中提及 THOP 是扩展要求，不代表现有导入器已经实现该格式。

## 6. 工厂职责与扩展方法

| 工厂 | 创建契约 |
| --- | --- |
| [ElementFactory](../../YQY/DataStructure/Factory/ElementFactory.h) | 创建六类现有单元；选项设置 CR3D 截面方向及 SPRING1/2 的内部 DOF（0～5）。调用方关联节点/属性、初始化运行状态并纳入模型 |
| [SectionFactory](../../YQY/DataStructure/Factory/SectionFactory.h) | `Create` 只分配类型，供导入恢复原始字段；`CreateCircular` 按面积计算半径，`CreateRectangle` 按宽高计算面积；`Clone` 原样复制几何、惯性和诊断字段，不重算 |
| [LoadFactory](../../YQY/DataStructure/Factory/LoadFactory.h) | 创建四类荷载并复制全部参数；调用方关联目标实体，跨模型复制后必须重新绑定弱引用 |
| [SolverFactory](../../YQY/Solver/Factory/SolverFactory.h) | 统一登记动力算法及执行策略，把只读 `AnalysisStep` 配置转换为调用方独占的 `unique_ptr<ISolver>`；旧 `Create_StepForSlover` 仅转发到 `Create` |

工厂负责对象自身的构造和参数复制，导入器负责字段校验及格式兼容，建模服务负责编号及关联，`StructureData` 负责复制模型中的引用重绑。不要在工厂内加入文件解析、界面提示或全局模型注册。

未知类型由创建工厂返回空指针；导入端仍保留各自既有策略，包括 HDF5 的未知单元回退、未知截面兼容和未知荷载跳过。求解器工厂对未知分析步以及未登记、未实现的动力算法返回空指针；中心差分和 HHT 仍未实现，不再回退为 Newmark。构造参数异常仍由调用方处理。

新增类型按下面顺序完成一条闭环：

1. 在相应基类下实现实体或 `ISolver`，补枚举及关键字映射；在对应工厂添加清晰的创建分支。
2. 保持调用方的编号、节点/属性关联和初始化责任。新增专属字段时同步复制、状态恢复及有效性校验，不能只让构造成功。
3. 按需要接入文本解析、HDF5 读写、导线建模、编辑/预览和后处理；外部字段和旧模型缺省值明确保持兼容。
4. 实现文件注册到工程，编译对应配置；执行类型基础检查、文本/H5 往返、连续两次模型复制及相关生产求解。数值实现改动另有独立参考值与容差验证。

当前文本线单元共用 `InputLineElements`，单元及荷载入口采用直接 `switch` 分派。有限且固定的类型集合不需要再包一层函数映射或转发 Lambda；只有真实运行期注册需求出现后，才考虑增加注册机制。

所有默认运行路径由 [ApplicationPaths](../../YQY/Application/ApplicationPaths.h) 统一生成。运行根目录为 `QStandardPaths::DocumentsLocation` 下的 `YQY`；文档目录不可用时采用 `AppDataLocation` 回退。当前机器是 `C:/Users/YQY/Documents/YQY`，不可把这个用户绝对路径写成其他机器的配置要求。

```text
文档/YQY/
├─ Projects/<源模型名>_<绝对源路径 SHA-1 前 10 位>/
│  └─ Results/                 H5 结果
├─ Results/                    无源模型时回退
├─ Export/
│  ├─ A结果/                   本次算例的 BDF 数据与曲线图
│  └─ A结果_1/                 同名算例或重新计算后的下一份导出
├─ GeneratedModels/            新生成模型
├─ Verification/<验证名称>/    验证默认产物
└─ Logs/                       程序日志
```

同名模型通过源文件绝对路径的 UTF-8 SHA-1 摘要隔离；默认结果名为 `<源模型名>.h5`，任务文件名为 `<源模型名>_case_<三位任务号>.h5`。已配置 H5 输出路径时优先使用其父目录，显式命令行输出目录优先于验证默认目录。任务重启沿用任务输出文件，不能把目录隔离误解成自动保存每次运行版本。

H5 内嵌模型的 `SOURCE_MODEL` 为空时，任务以实际导入文件路径定位项目。界面导出统一使用全局 `Export`，由 `Utility/ResultExportPaths` 按原始模型名生成 `A结果`，重名时依次创建 `A结果_1`、`A结果_2`。同一进程内以结果文件绝对路径、修改时间和大小识别结果版本；位移、单元、迭代步、能量及曲线图共用已分配目录，切换结果后返回仍复用，结果文件重新计算后分配新目录。

数据文件使用简短 BDF 名称，如 `A-节点27位移.bdf`、`A-迭代步.bdf`、`A-能量.bdf`。默认名称随节点和分量选择更新，手动编辑的路径保留；保存对话框优先显示本次结果目录，不受上次其他算例的保存目录影响。能量页可导出当前分析步勾选的完整时程，单位 J，缺失分量用 `NA` 表示；曲线导出由 BDF 生成同名 PNG/PDF，绘图脚本继续兼容历史 CSV 输入。已有旧导出文件不迁移。

资源查找先保留开发环境源码目录的既有优先级，再查找可执行文件相邻资源，以支持不携带 `.vcxproj` 的部署环境。`Import/Aero_Data/Output_Data` 是原始测量资源，`Input_Data` 含后续半周镜像数据，不能因为目录名有 `Output` 就搬走，也不能静默用镜像表替代原始表。

日志使用统一 `Logs`，保留现有格式、命名和轮换规则，不覆盖迁移前日志。`output/resultBatchFrames` 等是配置键，不是需要搬迁的文件夹。日常运行不应重新创建仓库根 `output`。
