# YQY 代码框架分析与重构说明

## 1. 当前框架

项目是基于 Qt、VTK、Eigen 和 HDF5 的 C++17 CAE 桌面程序，当前代码可以按职责划分为以下几层：

| 层级 | 目录 | 主要职责 |
| --- | --- | --- |
| 应用入口 | `Application`、`main.cpp` | 环境初始化、命令行验证、UI 审计和主窗口启动 |
| 界面层 | `GUI` | 主窗口、对话框、功能面板、模型视口和用户交互 |
| 应用控制层 | `GUI/Controllers` | 多模型文档管理、求解任务队列和后台任务状态 |
| 领域模型层 | `DataStructure` | 节点、单元、材料、截面、载荷、约束、分析步和结构模型 |
| 建模服务 | `Conductor` | 导线参数、属性库和导线有限元模型生成 |
| 求解层 | `Solver` | 静力、动力、时间积分、约束处理和求解器创建 |
| 输入输出层 | `Import`、`Export` | 文本模型导入、HDF5 模型与结果读写、BDF 结果导出 |
| 公共基础层 | `Base`、`Utility` | 基类、枚举映射、日志、模型管理和共旋工具 |

整体数据流为：

`文件导入 -> StructureData -> ModelController -> GUI/Viewport -> SolveTaskController -> Solver -> HDF5 -> 后处理显示/导出`

## 2. 主要耦合点

### 主窗口承担过多实现细节

`GUI/YQY.cpp` 同时包含主题绘制、路径查找、结果插值、进度动画、模型操作、任务管理、后处理和导出逻辑。主窗口应保留界面编排和事件连接，纯计算、路径策略和可复用控件行为应放入独立模块。

### HDF5 数据与读写器绑定

结果摘要、帧、节点结果、单元结果和范围结构原本定义在 `Hdf5ModelIO.h`。任何只保存或展示结果数据的界面都必须依赖完整读写器接口，造成不必要的编译依赖。

### 大型实现文件集中

当前主要热点为：

- `GUI/YQY.cpp`：主窗口和大量界面辅助实现；
- `Export/Hdf5ModelIO.cpp`：文件结构、模型序列化、流式结果和结果读取；
- `Conductor/ConductorModelBuilder.cpp`：几何、编号、附件和模型输出；
- `GUI/Widgets/ModelViewport.cpp`：VTK 场景、选择、交互和结果云图；
- `Import/Input_Model.cpp`：文件调度、各类实体解析和模型验证。

这些文件后续应按现有类的稳定职责逐步拆分，避免同时修改数据结构和算法。

## 3. 本次重构

### 应用路径独立

新增 `Application/ApplicationPaths`，统一负责模型导入目录、HDF5 结果目录和迭代结果目录定位。候选目录顺序、回退目录和自动创建行为保持不变。

### 结果数据与 HDF5 读写解耦

新增 `Export/Hdf5ResultData.h`，只保存结果 DTO。`YQY.h` 和 `ResultControlPanel.h` 不再包含完整的 `Hdf5ModelIO.h`；真正调用读写器的实现文件才包含读写器接口。

### 结果帧纯计算独立

新增 `Export/ResultFrameUtilities`，负责：

- 判断当前模型和结果文件内嵌模型是否一致；
- 对相邻结果帧的时间、载荷系数、位移、当前坐标、轴力、应力和应变进行线性插值。

计算容差、插值范围、字段处理顺序和缺失数据处理均保持原逻辑。

### 控件动画独立

新增 `GUI/Widgets/ProgressBarAnimation`，负责求解进度条的平滑追踪。定时器名称、16 ms 周期、步进比例和回退到零的行为保持不变。

## 4. 依赖原则

后续代码应保持以下方向：

- `GUI` 可以调用控制器和应用服务，不直接实现文件格式与求解算法；
- `Controllers` 负责任务和文档生命周期，不负责控件绘制；
- `Solver` 只依赖领域模型和求解接口，不依赖 GUI；
- `Import/Export` 负责格式转换，不负责界面提示；
- 数据传输结构放在轻量头文件中，避免把具体读写器传播到界面头文件；
- 仅在对象所有权或算法本身要求时使用直接依赖。

## 5. 后续安全拆分顺序

在继续保证计算逻辑不变的前提下，建议依次进行：

1. 将 `YQY.cpp` 的主题、图标和样式表提取到 `GUI/Appearance`；
2. 将主窗口的模型、分析、求解和结果槽函数分别移动到职责明确的实现文件；
3. 将 `Hdf5ModelIO.cpp` 按模型写入、结果流写入、结果读取和格式辅助函数拆分；
4. 将 `Input_Model.cpp` 按模型骨架、单元、载荷约束和验证拆分；
5. 将 `ModelViewport.cpp` 按场景构建、交互选择和结果可视化拆分；
6. 为结果插值、路径解析和 HDF5 数据契约增加独立自动化测试。

每一步都应先构建当前基线，再做单一职责迁移，最后执行模型导入、HDF5 读取和 UI 审计回归。
