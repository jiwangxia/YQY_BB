# 求解执行与收敛

本文将旧静力收敛修改说明与并行系统评估说明整理为现行求解手册。静力参数、常规路线和独立参考路线分别说明；历史示意参数 `tol`、`use_relative`、`verbose` 不再作为当前 `SolverStatic::Params` 接口。

## 2026-10-28 动力误差判据

当前动力算法将内部迭代与外部时间步误差分别处理；本轮不增加能量控制或通用能量输出。

- 普通 Newmark 和 TSSBN：以相邻实际迭代残差向量之差，或已施加的完整 Newton 位移修正量判断停止；非线性约束必须同时合格。残差变化除以 `max(1, ||Fext||)`，修正量范数除以 `max(1e-12, ||本步累计增量||)`，分别与分析步容差比较。首轮没有相邻残差，不允许直接认定残差变化为零；真正的零残差可以直接接受。Newmark 的线搜索缩短量不作为完整修正，也不以缩短步导致的小残差变化提前通过。
- Reference TSSBN：继续采用原参考完整残差向量的变化或修正量绝对范数，并保留原参考计数和约束判据。
- 自适应 Newmark/RK4 始终以归一化位移和速度粗细解误差的最大值接受或拒绝时间步；旧 `includeVelocityInError` 字段仅作输入兼容。
- 无 MPC 的普通及参考 TSSBN 计算真实辅助阶段 Y3 的加速度，再构造嵌入速度误差，避免外推公式使平动速度误差估计恒零。普通默认组合为 `max(Eu, Ev)`，参考默认组合为 `sqrt((Eu²+Ev²)/2)`；其余已选范数仍保持各自定义。辅助加速度求值是构造速度估计所需的运动方程计算，不是加速度误差控制。
- 普通 MPC 路径保留实际整步/两半步的位移、速度及姿态比较；参考 MPC 保留原投影与速度探针。
- 已移除独立加速度误差接受门、对应步长控制及界面参数。加速度状态、惯性力、约束运动学和端点恢复继续计算。旧 HDF5 加速度控制数据集读取并校验后忽略，新保存文件不再写入该数据集；旧 TSSBN 检查点因策略签名变化不能直接续算。

残差变化小或修正量小不等于当前平衡残差必然小。这是本次选定的停止策略，其适用精度需由独立物理参考及步长加密检查；下文历史记录中的旧残差门、外推估计和已取消加速度门不代表本节现行策略。

## 静力参数与判据

当前参数定义见 [SolverStatic.h](../../YQY/Solver/Static/SolverStatic.h)，执行逻辑见 [SolverStatic.cpp](../../YQY/Solver/Static/SolverStatic.cpp)。结构体默认值为：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `numIncrements` | 10 | 荷载增量数 |
| `maxIter` | 32 | 每个增量最大 Newton 迭代次数 |
| `tol_R` | `1e-4` | 残差容差 |
| `tol_dx` | `1e-6` | 位移修正容差 |
| `tol_C` | `1e-10` | 非线性约束容差 |
| `referenceEquilibrium` | false | 采用独立参考平衡路线 |
| `referenceTimeStep` | 0 | 参考路线的时间步配置 |

这些是结构体默认值；工厂会根据实际分析步配置设置参数，不能用本表代替运行模型的配置。调参前先检查单位、约束、材料、荷载和增量设置，不通过放松容差掩盖奇异或模型错误。

常规路线使用消元后的求解残差 `R`；无 MPC 时直接使用结构残差。令 `S` 为整个静力荷载路径保留的残差尺度，初始为 1，每个增量首轮用 `max(S, ||R||)` 更新，避免随增量反复缩小到舍入误差量级。

```text
力收敛 F：      ||R|| < tol_R * S
强力收敛 Fs：  ||R|| < 0.05 * tol_R * S
位移收敛 D：   relativeIncrement < tol_dx
约束收敛 C：   constraintNorm < tol_C
```

`relativeIncrement` 为当前修正范数除以本荷载增量已累积修正范数；累积范数不超过 `1e-12` 时改用修正绝对范数。首轮以 `F && C` 判断；后续以 `((D && F) || Fs) && C` 判断。强力收敛分支允许在残差已远低于阈值时通过，不能把当前算法简化为旧文档中的“任何情况都必须同时满足位移和力判据”。

非线性 MPC 的约束残差独立检查，消元主元或线性系统失败会停止求解。达到最大迭代次数仍不收敛时，任务应失败，不能把已有部分结果解释为完整通过。

独立参考路线采用修正量和相邻右端项变化的绝对判据：二者之一满足相应容差，且约束收敛时才通过。这条路线与常规归一化判据的容差含义不同，不能混用两条路线的性能或收敛结果。

## 诊断与调参

静力诊断可通过 `YQY_PROFILE_STATIC` 开启，非收敛记录包含当前增量、残差及阈值、修正指标和约束指标。优先检查：

1. 刚体自由度是否受约束，规定约束和 MPC 是否冲突，从自由度 Jacobian 是否奇异。
2. 节点、单元、属性及荷载引用是否有效，力/力矩和位移/转角单位是否一致。
3. 荷载增量、初始状态和非线性迭代次数是否适合当前问题。
4. 指标是舍入误差平台、实际不平衡还是约束失败，再确定是否调整容差。

动力积分器的时间误差、Newton 残差和 MPC 运动学约束是不同的误差来源，分别见 [时间积分与阻尼](时间积分与阻尼.md) 和 [MPC 约束理论与实现](MPC约束理论与实现.md)。

## 系统评估与并行执行


### 职责边界

`AnalysisStep` 管理模型状态、单元与稀疏矩阵结构；时间积分器只管理时间步、迭代和线性方程求解。
两者通过 `IAnalysisModel::EvaluateSystem` 交换本次迭代需要的系统贡献，避免积分器直接了解单元装配细节。

### 一次隐式迭代的执行顺序

1. Newmark 或 TSSBN 创建“外力 + 有效切线”的请求。
2. `IAnalysisModel` 将请求转发为刚度、质量、速度切线、构型切线和外力切线的计算。
3. `AnalysisStep` 按局部矩阵规模估算装配代价；工作量不足时直接串行，达到门槛后再使用共享线程池。
4. 每个工作线程只写入自己的局部缓冲区；主线程按固定顺序归并到稀疏矩阵与惯性力，保证结果可重复。
5. 积分器叠加外力切线、施加非线性 MPC 消元并调用线性求解器。

RK4 使用“显式动力学”请求，只刷新内力、惯性力和外力，不再生成未使用的速度切线与构型切线。常质量模型只在第一次阶段计算时装配并分解质量矩阵，后续阶段同时复用质量矩阵及其分解；状态相关质量模型仍会逐阶段重算。

### 性能策略

- 单元计算和外载数值切线使用同一共享线程池，避免为不同物理贡献创建独立线程池。
- 并行装配与 PARDISO 线程数分别控制；基准测试固定 PARDISO 为 1 线程，只衡量装配加速。
- 大规模且颜色数量较少的模型可采用图着色直接写入；其他模型采用局部缓冲归并，优先保证线程安全和确定性。
- 单元类型批次、工作区间和矩阵容量与稀疏装配模式一同缓存；只有自由度或拓扑重新初始化时才失效。
- 有效切线的各分量直接写入预先定位的稀疏矩阵数值槽，避免为每个单元生成临时等效矩阵。
- 达到运行时校准门槛后，桁架、常规四自由度索、共享六自由度索和 CR3D 梁可在 GPU 上批量计算有效切线、内力与惯性力；残差模式不会回传或累加未使用的整体矩阵。未达到门槛或暂不支持的单元走 CPU 并行回退路径。
- 纯桁架、纯常规索和纯 CR3D 梁模型可把设备端 CSC 数值直接交给 cuDSS；混合模型将 GPU 批次数值在设备端合并，CPU 剩余单元的非零增量单独上传后也可直接求解。含刚体惯量等暂未纳入设备端增量的模型保留原主机回退。
- 自动模式先预热 GPU，再用相同试探状态实测 CPU/GPU 装配和 PARDISO/cuDSS 求解；只有结果符合容差且 GPU 明显更快时继续使用 GPU。
- `AnalysisStep` 会累计系统评估、有效切线、动力系统、外载切线、残差和结果写出耗时；系统评估另给出扣除已计时子项后的自身耗时。父项包含子项，不直接相加。
- 界面任务耗时从点击启动算起，自动导入 H5 并显示首帧后才停止；求解器内部耗时另行报告，用于区分排队、模型复制和后处理开销。
- 任务完成报告同时给出进程峰值内存、GPU 实际使用次数、CPU 回退原因以及各主要阶段耗时。
- 使用 `--isolated-solve` 可试验完整算例的独立工作进程。一个完整算例的全部分析步留在同一工作进程，报告该进程的峰值工作集及 PID；数值包含工作进程自身开销，但不混入其他并发算例或界面内存。指定分析步仍使用原线程路径，并继续明确标注其内存是进程级指标。
- 独立进程的启动、模型快照、求解和结果导入均计入界面总耗时。小算例可能因启动与快照开销变慢，因此该模式暂不默认开启。
- 多个独立算例并行时，任务调度器按最大并发任务数均分可用 CPU 预算，并将同一份预算传给区域并行、单元装配和 PARDISO，避免嵌套并行导致超订阅。
- 单个算例可使用更高的 CPU 预算；并发上限变大时，每个算例的预算会相应收紧。正在运行的任务保持启动时的预算，后续任务遵循新的设置。
